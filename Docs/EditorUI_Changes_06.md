# モデル指定・責務の再配置・シーンの保存 変更まとめ（第6回）

対象 : Engine / Editor / Game / Application
ビルド : Debug x64 でエラー・警告 0。
起動して一連の操作を行っても、D3D12 デバッグレイヤーのメッセージは 0。終了も正常。

今回の依頼は次の6点。

1. MeshComponent などのモデルをエディタ上から指定できるようにする
2. 可読性の低いコードが多いので、分かりやすさに力を入れる
3. `GameObjectFactory` など、置き場所が怪しいものを正しい場所へ
4. マウスカーソルの形がおかしくなる問題
5. シーンの保存と選択
6. エンジンの構造と使い方の資料

**先に結論** : 3 が今回の中心です。
1 と 5 を素直に作るには、そもそも「誰が何を持つか」が正しくないと作れませんでした。

---

## 1. 置き場所の見直し（責務の再配置）

### 判断の基準を先に決めた

`GameObjectFactory` が Editor にあるのは正しいのか、というご指摘から始めました。
個別に考えると迷うため、まず基準を1つ決めています。

> **エディタが無い状態（ゲームとして起動したとき）でも必要か？**
> 必要なら Engine、編集画面にしか関係しないなら Editor。

`GameObjectFactory` がやっているのは
「オブジェクトを作る」「名前が重複しないようにする」「中身を写す」の3つで、
エディタ固有のものは1つもありません。実行中にプレファブを配置する場合にも必要です。
→ **Engine へ移動**。

同じ基準で見直した結果が次の表です。

| もの | 変更前 | 変更後 | 理由 |
|---|---|---|---|
| `GameObjectFactory` | Editor | **Engine/GameObject** | エディタ固有の処理が無い |
| `ComponentRegistry` | Editor | **Engine/GameObject** | ファイルからの復元に必須 |
| `PrefabAsset` | Editor | **Engine/Asset** | 完成したゲームもプレファブを読む |
| `ComponentInspectors` | Editor | Editor（そのまま） | 表示名や描き方は編集画面の都合 |
| `PrefabSystem` | Editor | Editor（中身を縮小） | 保存先の決定とUndoだけを残した |

### ComponentRegistry を2つに割った

以前の登録表は、性質の違う2つを1つに混ぜていました。

```
変更前 : ComponentTypeInfo（Editor）
    TypeName / DisplayName / IsRemovable
    Has / Add / Remove / Save / Load
    DrawInspector
    ↑ 「型の扱い方」と「画面での見せ方」が同居している
```

これを次のように割りました。

```
変更後
  Engine : ComponentTypeInfo      TypeName / Has / Add / Remove / Save / Load
  Editor : ComponentDisplayInfo   TypeName / DisplayName / IsRemovable / Draw
```

エディタ側は型名で引き当てます。
**エンジンに型を足して、エディタへの登録を忘れても表示は壊れません**
（型名がそのまま表示名になります）。

登録は2か所になりますが、それぞれ意味が違います。
一方は「このコンポーネントは何であるか」、もう一方は「エディタでどう見せるか」です。

### 依存の向きが一方通行になった

```
Application → Editor → Engine → RHI
     └────→ Game ────┘
```

`Engine` から `Editor` を参照している箇所は0になりました。

## 2. モデルをエディタから指定する

### なぜ今まで指定できなかったか

モデルの GPU リソース（`Mesh` / `Material`）を **`GameScene` が抱えていた**ためです。

```
変更前
  GameScene
    ├ m_Meshes      ← モデルの実体を所有
    ├ m_Materials
    └ m_MeshComponents  ← 初期化時に作ったコンポーネントのキャッシュ
```

この形だと

* エディタからモデルを割り当てても、**誰がそのGPUリソースを持つのか決まらない**
* 同じモデルを2体置くと **GPU上に2回読み込まれる**
* エディタで `MeshComponent` を後から足しても、キャッシュに入らず
  **カメラ行列もスロット番号も渡されない**（＝何も描かれない）

という問題がありました。3つ目は、前回までの実装に残っていた不具合でもあります。

### ModelLibrary を作った

`Engine/Resource/ModelLibrary` を新設し、読み込みと所有をここへ集めました。

| | 変更前 | 変更後 |
|---|---|---|
| 所有者 | GameScene | **Application**（シーンより長生き） |
| 同じモデルを2体 | 2回読み込む | **1回だけ**（キャッシュ） |
| シーン切り替え | 読み直し | 読み直さない |
| パスの扱い | 絶対パス | **プロジェクトからの相対パス** |

相対パスにしたのは、プレファブやシーンのファイルへ絶対パスを書くと、
プロジェクトを別の場所へ移した時点で開けなくなるためです。

### 「希望」と「実体」を分けた — 今回いちばんの設計

`MeshComponent` が持つのは **「どのモデルの何番目を描きたいか」という希望だけ**にしました。
実際にGPUリソースを結び付けるのはシーンの仕事です。

```
MeshComponent
    m_ModelKey / m_PartIndex          ← 希望（保存できるただの値）
    m_AppliedModelKey / m_AppliedPart ← いま実際に結び付いているもの

    NeedsModelUpdate()   2つがずれていたら true
```

```
GameScene::SyncRenderComponents()   毎フレーム
    1. 定数バッファがまだ無いものを用意する
    2. ずれているものだけ、ModelLibrary から実体を引いて結び付ける
    3. 全部にカメラ行列とフレーム番号を渡す
```

**なぜ分けるのか**

コンポーネントが自分でモデルを読もうとすると、デバイスもモデルの置き場も
知らなければならず、「ただのデータ」ではなくなります。すると保存も復元もできません。

希望だけを持たせると、次の3つが同時に成り立ちます。

* コンポーネントは保存・復元できる値のままでいられる
* **エディタから割り当てても、ファイルから読み込んでも、同じ道を通る**
* モデルがまだ読み込まれていなくても、あとから解決される

副産物として、**初期化時のキャッシュが不要になり**、
エディタでコンポーネントを増減しても正しく描かれるようになりました。

### 画面

インスペクタの Mesh / Meshlet に「モデルを選択」を追加しました。
一覧は `Assets` 以下のモデルファイル（`.fbx` / `.obj` / `.gltf` / `.glb`）を、
メニューを開くたびに走査して作ります。

`Part`（モデル内の何番目のメッシュか）も指定できます。
1つのモデルは体・髪・服のように複数のメッシュに分かれているためです。

モデルの変更は**取り消せます**。
そのために、型ごとの専用コマンドではなく
「コンポーネントの値の変更」を1つのコマンドにまとめました。

```cpp
// 保存 / 復元の経路をそのまま使うため、
// 保存できる値であれば何を変えてもUndoできる
ComponentCommands::SetValues(ctx, obj, typeInfo, before, after);
```

## 3. シーンの保存と選択

`.scene` ファイル（JSON）として保存・読み込みできるようにしました。

### プレファブの仕組みを使い回した

シーンの中身は「置いてあるオブジェクトを1体ずつ設計図にしたものの並び」です。
1体分を値へ写す処理はプレファブのためにすでにあるため、そのまま使っています。

```
SceneAsset
    Name
    Objects : vector<PrefabAsset>    ← 1体分はプレファブとまったく同じ形
```

シーン用にもう一組作ると、コンポーネントを増やすたびに2か所へ手を入れることになり、
片方だけ忘れる原因になります。

### 操作

メニューバーに「シーン」を追加しました。

| 項目 | 動作 |
|---|---|
| 上書き保存 | 今開いているファイルへ保存 |
| 名前を付けて保存 | コンテンツブラウザの現在フォルダへ `.scene` を作る |
| 選択シーンを開く | 選んでいる `.scene` を開く |
| 新規シーン | すべて削除して空にする |

コンテンツブラウザで `.scene` をダブルクリックしても開けます。

### 検証中に見つけて直した不具合

最初の実装では、**シーンを開くとその場で固まりました**。

原因は、オブジェクトを消すと同時にコンポーネントの定数バッファも解放されるが、
**GPUがまだそれを読んでいる最中だった**ことです。
コマンドリストはCPUより1〜2フレーム遅れて実行されます。

中身を捨てる前に `WaitForGPU()` を入れて解決しました。
第3回でエフェクトエディタを閉じたときに固まったのと、まったく同じ原因です。

### 制限

* シーンを開くと **Undo履歴は消えます**（オブジェクトが作り直されるため）
* 保存されるのは `GameObjectManager` の中身だけです
  （カメラ位置やポストエフェクトの設定は、まだ `GameScene` のコードが直接持っているため）
* `MeshletComponent` を含むシーンは、開き直すときにメッシュレット分割を
  やり直すため数秒かかります

## 4. マウスカーソルの問題

### 原因

```cpp
// 変更前
wc.hCursor = LoadCursor(hInst, IDC_ARROW);
```

第1引数にモジュールハンドルを渡していました。
この形は「**このexeの中にある、その名前のカーソル資源**」を探しに行きます。
`IDC_ARROW` はシステムのカーソルなので当然見つからず、**`hCursor` に `NULL` が入ります**。

`hCursor` が `NULL` のウィンドウは、カーソルの形をOSに任せきりになります。
そのため**ウィンドウ枠でリサイズ矢印になったあと、中へ入っても矢印のまま戻らない**という、
ご報告どおりの症状が出ていました。

```cpp
// 変更後
wc.hCursor = LoadCursor(nullptr, IDC_ARROW);
```

検証 : ウィンドウクラスの `hCursor` が `IDC_ARROW` と一致することを確認（変更前は `NULL`）。

### ついでに形も出し分けるようにした

せっかくなので、場所に応じてカーソルの形が変わるようにしました。

| 場所 | 形 |
|---|---|
| 文字入力欄の上 | Iビーム |
| ウィンドウ右下のリサイズグリップ | 斜めの両矢印 |
| それ以外 | 矢印 |

**責務の分け方**

`EditorUI` は Windows の API を知りません（知らせない設計にしています）。
そこで EditorUI は「こう見せたい」という**希望を立てるだけ**にして、
実際に `SetCursor` を呼ぶのは `Application` にしました。

```
ウィジェット : ctx.RequestMouseCursor(MouseCursor::TextInput)
                        │  希望は毎フレームNewFrameで矢印へ戻す
                        ▼
Application  : WM_SETCURSOR で希望をWin32のカーソルへ翻訳する
```

## 5. 可読性

今回触った範囲で、次を徹底しました。

**GameScene を書き直した**

いちばん読みづらかった箇所です。

| | 変更前 | 変更後 |
|---|---|---|
| 行数 | 約400行 | 約340行（処理は増えている） |
| メンバ | Mesh/Material/コンポーネントのキャッシュを保持 | シーンに要るものだけ |
| 初期化 | `InitMeshes` / `InitGameObjects` / `InitMeshlets` の3つに分散 | `InitDefaultObjects` 1つ |
| 毎フレーム | `UpdateViewProj`（キャッシュ前提） | `SyncRenderComponents`（実態を毎回見る） |

**共通化して重複を消した**

* テキストアセットの読み書き → `Engine/Asset/AssetTextFile` へ集約
  （プレファブ・シーン・ウィンドウ設定が同じ処理を持っていた）
* 生存確認 → 各コマンドの `IsTargetAlive()` へ集約

**コメントの方針**

「何をしているか」はコードを読めば分かるため、
**「なぜそうしたか」「そうしないと何が起きるか」**を書くようにしています。

```cpp
// 見つからなかった場合もApplyModelは呼ぶ
// 呼ばないと「ずれたまま」と判断され、毎フレーム読み込みを試み続ける
_component.ApplyModel(pMesh, pMaterial);
```

**既存の警告も直した**

`Renderer.cpp` の `D3D12_RECT` へ `0.0f` を代入していた箇所（C4244 警告2件）を修正しました。

## 9. 残っている課題

| 項目 | 内容 |
|---|---|
| シーンに保存されない情報 | カメラ位置やポストエフェクト設定は `GameScene` が直接持っているため保存対象外です。`SceneAsset` へ項目を足せば対応できます |
| プレファブの連動 | 設計図を直しても、置いてあるものには反映されません |
| 複数選択 | 選択は常に1つです |
| 親子関係 | 「グループ」は目印だけで、実際に子を持てません |
| メッシュレットの読み直し | シーンを開くたびに分割をやり直すため数秒かかります。分割結果をキャッシュすれば解消できます |
| モデル一覧の走査 | メニューを開くたびに `Assets` 以下を走査します。ファイル数が増えたら `AssetDatabase` 側の監視結果を使う形にします |
